# Phase 193 — Unreferenced i18n Key Audit

**Status:** complete. **Verdict on the cluster:** the protection and
intelligence surfaces are ALIVE and rendered; their unreferenced keys are
retained vocabulary, not dead weight. Two disconnected-consumer defects were
found and fixed. Five keys were proven dead and removed.

Generated evidence (regenerated by the guard on every run, never hand-written):

- `docs/i18n-key-usage.json` — per-key consumer evidence
- `docs/i18n-key-classification.json` — per-key category + reason
- `scripts/i18n-key-usage-report.mjs` — the scanner
- `scripts/i18n-classify-keys.mjs` — the classifier

## 1. Why the headline number changed

The figure carried into this phase was *"122 unreferenced of 944"*. Measured
properly it is **270 unreferenced of 973**. The earlier number was not wrong so
much as measuring something else:

| Difference | Effect |
| --- | --- |
| Counted 944 string leaves vs 973 canonical keys | different denominators |
| Counted a `*.test.*` reference as a consumer | hid test-only keys |
| No import-graph reachability | a key used only by an UNMOUNTED component looked "used" |
| Did not follow `t.x.y.replace(...)` | briefly *over*-reported (fixed below) |

**A single grep is not evidence.** Three separate scanner defects were found and
fixed *during* this audit — each one would have produced a confidently wrong
delete list:

1. member access running past the leaf into a string method
   (`t.system.historyCount.replace(...)` parsed as `…historyCount.replace`);
2. no distinction between a mounted and an unmounted consumer;
3. no credit for indirect consumers such as `enum-mapping.ts`.

## 3. Production defects found and fixed

### D1 — `MarketOverviewPanel` rendered its provenance badge in English only

`market.live`, `market.stale`, `market.unavailable` were translated into all
nine locales. Every parity guard was green. The component rendered the literal
strings `"LIVE"` and `"STALE"`, plus an English-only legend.

This is the **MISSING CONSUMER** case exactly: translation existed, surface
existed, the wire between them did not. Deleting the keys would have "fixed"
the audit while leaving non-English users reading an untranslated claim about
how current their market data is — a silent breach of invariant 2.

**Fixed:** the badge now renders `t.market.live` / `t.market.stale`, carries an
`aria-label` (a bare `—` is meaningless to a screen reader), and the legend
renders the new key `market.sourceTransparency`, translated in all nine locales
with the LIVE/STALE tokens preserved because the badge still displays them.

`MarketOverviewPanel` was removed from `COMPONENT_DEBT` — the ratchet shrinks
**15 → 14**.

### D2 — the guard could not see one-word hardcoded claims

The Phase 189 detector requires two consecutive words, because single tokens
are usually punctuation or units. `{isLive ? "LIVE" : "STALE"}` slipped through
that rule for 4 phases.

**Fixed:** added `hardcodedStatusTokens()`, which flags ALL-CAPS literals
rendered from a JSX expression. It is deliberately narrow and was tuned against
real code until it produced **zero false positives** while still catching the
real defect. It does NOT fire on:

- type unions (`plan: "GUEST" | "PREMIUM"`)
- equality comparisons selecting a CSS class (`x === "SUPPORTING" ? cls : cls`)
- enum arguments to a translating mapper (`mapSeverity("CAUTION", t)`)
- constant lookups (`SEVERITY_COLORS.NONE`), `?? "NONE"` data defaults
- untranslated-by-design notation (BOS, CHoCH, FVG, DXY, WTI, W1/D1/H4…)

`system.stale`, `system.unavailable`, `system.updated`, `system.intelligence`,
`system.alerts` — superseded uppercase variants (`"STALE"`), replaced by the
`*Label` forms (`"Stale:"`) that `RuntimeHealthDashboard` — the mounted system

Proof applied to each, per §6:

- no production consumer;
- no consumer in the UNMOUNTED panels either;
- no dynamic access (the only production dynamic site is `tx(key)` in `index.ts`);
- no dot-path string literal anywhere;
- no test exercising them as a production path;
- the `*Label` replacement is present and rendered.

Removed from all nine locales **and** `types.ts`, so the compiler enforces it.
Leaf count 977 → 973 (−5 dead, +1 `market.sourceTransparency`).

## 6. Dynamic lookup findings

Audited for `t[expr]`, `t.section[expr]`, `tx(variable)`, `txi(dynamicKey, …)`,
template-literal key construction, loops over keys, and config-derived labels.

**Exactly one production dynamic site exists:** `tx(key)` inside
`src/lib/i18n/index.ts` — the helper's own definition. Three further sites are
in a single test file. The guard asserts this and **fails if a component starts
constructing keys at runtime**, because static analysis would stop being
sufficient at that moment.

`describeFreshnessForUser` in `provenance-copy.ts` duplicates `mapFreshness` in
`enum-mapping.ts`. Flagged as a duplicate-engine risk; **not** resolved here
(out of scope), recorded so it is not rediscovered.

## 7. Retained-but-unreferenced: the honest reason

258 keys are retained. The dominant reasons:

| Cluster | Keys | Why retained |
| --- | --- | --- |
| `intelligence.*` | 72 | dashboard mounted and using 87 keys; rest are dimension labels not in the current layout |
| `protection.*` | 41 | surface mounted; invariant 6 forbids touching protection state machines |
| `journal.*` | 29 | journal states not yet rendered |
| `system.*` | 29 | operator diagnostics; `MarketDataHealthPanel` built but unmounted |
| `fundamental.*` | 13 | treasury/COT/EIA blocks render only with provider evidence — **BLOCKED**, so unreachable today |
| `global.*` | 12 | shared primitives; deleting them guarantees the next form hardcodes English |

The `fundamental.*` case is the clearest argument against a delete-by-count
policy: those branches cannot execute while live providers are BLOCKED, so
static analysis *must* see them as unused. Deleting them would break the
surface the moment providers connect.

## 8. Guard and budget

`src/lib/i18n/orphan-key-guard.phase193.test.ts` (14 tests) regenerates the
report on every run — it can never assert against a stale artifact.

- ratchet `UNREFERENCED_BUDGET = 270`, may only shrink; a separate test rejects
  an absurdly slack budget;
- `INTENTIONAL_ALLOWLIST` is **self-validating in both directions**: an entry
  whose key no longer exists fails, and an entry whose key *gained* a consumer
  fails, so the allowlist cannot become a hiding place;
- vacuity probes: asserts >600 keys are referenced and that known-rendered keys
  are never reported unreferenced.

**Honest scope:** this is static analysis over the import graph. It proves a key
is reachable from a mounted module — **not** that a human saw it. Actual
rendering is covered by the surface tests and by HUMAN UAT.
